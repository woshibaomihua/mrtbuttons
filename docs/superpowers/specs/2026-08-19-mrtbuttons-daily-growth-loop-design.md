# MRT Buttons 每日 SEO / GEO 增长闭环设计

- 日期：2026-08-19
- 状态：设计已由用户确认，等待书面规格复核
- 站点：`https://mrtbuttons.com`
- 唯一正源：`E:\Claude\mrtbuttons`
- 运行时间：北京时间每天 07:30

## 1. 目标

建立一个附着在当前 Codex 任务上的有状态每日增长闭环。它每天先读取真实状态，再决定“修复、优化、生成候选或不改站”，持续提升以下四类结果：

1. Google/Bing 可发现、可抓取和可索引性；
2. 有真实搜索数据支撑的 SEO 排名与点击机会；
3. Google 生成式搜索、ChatGPT 等答案系统理解和引用本站的能力；
4. 访问者进入网站后的询盘可用性、归因能力与转化质量。

该任务不承诺具体排名。Google 官方说明指出，满足技术要求不等于保证收录；GEO/AEO 也不是独立于基础 SEO 的排名捷径。系统的职责是稳定完成可控动作、记录外部结果，并根据新证据调整下一步。

## 2. 非目标

- 不为了“每天有产出”而强行修改网站；
- 不每天发布文章或批量生成关键词变体页；
- 不重复请求同一 URL 编入索引；
- 不对未实际变化的页面伪造 `lastmod`；
- 不编造 MOQ、价格、交期、认证、客户、产能、评分或案例；
- 不自动购买外链、投放广告或以马甲在 Reddit/论坛自荐；
- 不自动发布新博客、LinkedIn、Reddit、目录站或数字 PR 内容；
- 不运行已过时的 `sitegen.py` 或任何 `gen_*.py` 生成器。

## 3. 选定方案

采用“单一有状态 Heartbeat + 周期感知”的结构，而不是多个会并发修改仓库的独立任务。

每日 Heartbeat 固定在北京时间 07:30 运行。它识别星期、月份和上次状态，在一个任务中切换每日、每周和每月工作，并把结果继续写回当前任务。这样可以保留上下文、减少重复审计，并避免多个自动任务同时编辑 `main`。

### 3.1 为什么不采用其他方案

- 单一“大而全”日报：每天重复相同检查，容易制造无效提交和重复索引请求；
- 日/周/月三个独立任务：职责清楚，但共享同一仓库、浏览器登录态和部署通道，存在并发冲突；
- 周期感知 Heartbeat：每天都有明确目标，同时只有一个写入者，最符合本站当前规模。

## 4. 数据源与事实优先级

按以下顺序决定当天行动：

1. 当前生产页面的 HTTP、正文、canonical、robots、sitemap、表单和结构化数据；
2. `E:\Claude\mrtbuttons` 当前已提交页面和 `data\product-data.json`；
3. GSC 正确属性 `sc-domain:mrtbuttons.com` 的最新完整日期数据；
4. Bing / IndexNow 的提交和抓取回执；
5. 已验证的 Formspree、GA4、AI 引荐及询盘数据；
6. 买家真实问题、SERP、Reddit/LinkedIn/行业目录等站外公开信号；
7. 企业提供且可追溯的证书、报价、样品、质检、生产与客户证据。

外部建议、行业手册和第三方统计只能用于生成假设，不能覆盖本站真实数据或成为未经核验的页面宣称。

## 5. 每次运行的数据流

### 5.1 预检

1. 读取 `E:\Claude\_lib\sites.json`，确认唯一正源与部署方式；
2. 检查 `E:\Claude\COORDINATION.md` 是否有 MRT Buttons 冲突任务；
3. `git fetch` 后比较本地 `HEAD`、`origin/main` 和工作区状态；
4. 工作区脏、远端领先或有人认领重叠范围时，停止写入，只生成冲突报告；
5. 检查 GSC 专用 Chrome CDP 9230；未登录时继续完成无登录巡检，不绕过认证。

### 5.2 每日健康检查

- sitemap 中所有 canonical URL 的生产状态；
- 首页、Contact、主要品类、robots、sitemap、`llms.txt` 和 IndexNow key；
- canonical、robots、H1、JSON-LD、内部链接和图片引用；
- Formspree 端点、公开邮箱、WhatsApp、电话及 JavaScript 回退；
- Googlebot、OAI-SearchBot、GPTBot、ClaudeBot、PerplexityBot 等访问结果；
- 新增 404、5xx、重定向链、意外 noindex、错误 canonical 和孤立页；
- GSC 新错误、新查询、点击/曝光/CTR/排名变化及索引覆盖变化。

### 5.3 决策

| 等级 | 条件 | 自动动作 |
|---|---|---|
| P0 | 生产 5xx、关键页不可访问、表单失效、robots/noindex 误封、邮箱或主要询盘入口错误 | 认领范围，最小修复，全量验证，统一部署并报告 |
| P1 | GSC 或生产证据指向一个明确页面问题，且修复不需要新增未经核验事实 | 可自动优化现有页面、内链、title/meta、可见答案、schema 一致性并部署 |
| P2 | 新内容、外部提及、认证/客户/产能等新事实、目录提交、社媒发布、付费动作 | 只生成候选、证据需求和预期收益，等待用户确认 |
| No-op | 没有新证据、变化不显著或外部数据仍在延迟 | 不修改、不提交、不部署；记录“今日不改站”及观察项 |

### 5.4 提交与部署

- sitemap 只加入 canonical、indexable、生产 200 的新 URL；
- `lastmod` 只更新真实修改过的 URL；
- IndexNow 只提交新增、实质更新、删除或迁移的 URL；
- GSC Request Indexing 只用于少量新增或实质更新的高优先级 URL；相同 URL 不重复请求；
- 所有站点修改必须通过 `E:\Claude\_lib\deploy.ps1 -Site mrtbuttons`；
- 只有脚本输出字面值 `DEPLOY_OK` 才能报告部署成功；
- 部署后重新读取生产正文，而不只检查 HTTP 200。

## 6. 每周工作节奏

| 星期 | 当日主目标 | 最大写入范围 |
|---|---|---|
| 周一 | GSC 近 28 天与上一周期对比，筛排名 4–20、低 CTR、新查询和索引变化 | 只生成本周 3 个优先目标 |
| 周二 | 优化 1 个已有机会页 | title/meta、买家直答、采购变量、真实证据和 3–5 条正文内链 |
| 周三 | GEO / AI 推荐差距 | 现有页面实体一致性、可引用答案、证据边界及来源组织 |
| 周四 | 询盘转化与归因 | Formspree、WhatsApp、邮箱、CTA、事件和手机体验 |
| 周五 | 收录与内容治理 | 未收录页、孤立页、重复意图、旧内容和真实 `lastmod` |
| 周六 | 买家问题和站外话题研究 | 只生成候选内容与证据清单，不自动发布 |
| 周日 | 周报、衰减检查和下周目标 | 无 P0 时不修改网站 |

任何一天发现 P0，P0 优先于星期主题。

## 7. 每月与季度节奏

### 每月

- 在最后一个完整 28 天窗口上生成 GSC 月度对比；
- 使用固定的 20 个买家问题，分别记录可访问平台的品牌提及和本站引用；
- 区分 Google、Bing、ChatGPT/其他 AI、LinkedIn、邮件、WhatsApp 与直接访问；
- 检查 Formspree 用量、邮箱送达、GA4 事件和 AI referral；
- 复核已优化页面是否真实提升，不把短期波动当成结论；
- 输出下月仅 3 个最高价值目标。

### 每季度

- 全站技术与内容差异审计；
- 竞争页面、独有数据资产和实体提及差距复核；
- 旧内容衰减、过期事实、证据台账与外部条目一致性复核；
- 仅在有可追溯样本时提出新的 Benchmark / Report / Statistics 数据资产页。

## 8. 30 / 60 / 90 天目标

### 30 天：测得准、收得住

- 关键生产页面、表单、邮箱、robots、sitemap 和 canonical 每日检查通过；
- Formspree 新邮箱完成账号侧验证和一次真实测试询盘闭环；
- 获得真实 GA4 Measurement ID 后，验证表单、WhatsApp、邮箱、电话和目录下载事件；
- GSC 有效索引覆盖运营目标不低于 95%，未收录 URL 均有原因与处理记录；
- 建立非品牌词、品牌词、询盘来源和 AI 提及的首月基线；
- 不产生重复意图页面或无证据内容。

### 60 天：已有机会页开始改善

- 按 GSC 证据完成 4–8 个已有页面优化；
- 每个目标页补足买家直答、采购变量、可核验事实和上下文内链；
- 形成至少 4 个经过关键词冲突检查的新内容候选，经用户批准后才发布；
- 孤立页、错误 canonical 和无效结构化数据保持为 0；
- 完成至少两轮询盘路径或 CTA 检查，一次只验证一个假设。

### 90 天：形成可复用增长循环

- 非品牌曝光以月环比增长 10% 作为运营目标，不作为搜索引擎结果承诺；
- 选中的排名 4–20 机会词中，目标 30% 在 28 天内提升至少 3 位，或 CTR 相对提升至少 20%；
- 有效索引覆盖稳定在 95% 以上，未收录问题不持续扩大；
- 每月完成一次固定 20 问 AI 提及/引用测试，第 90 天目标至少获得 2 次有效品牌提及或本站引用；
- 询盘来源可区分主要搜索、AI、社交、邮件、WhatsApp 与直接访问；
- 每周始终只保留 3 个最高价值目标。

目标失败时必须记录基线、外部限制和下一假设；不得通过改口径或删数据制造达成。

## 10. 错误与阻塞处理

- GSC 未登录：完成站内和生产巡检，标记“GSC 数据未刷新”，不绕过登录；
- GSC 数据延迟：使用最后一个完整日期并明确截止日；
- CDP 端口监听但无活动目标：判定浏览器不可用，不把端口存在当成登录成功；
- 工作区脏或协作冲突：停止写入和部署，报告冲突文件及责任范围；
- Formspree/GA4 账号侧设置未完成：列为外部依赖，不声称转化链路已完成；
- 生产验证失败：停止成功声明，保留 commit 和失败证据，优先恢复关键功能；
- IndexNow HTTP 200：只报告“已接收”，不报告“已收录”；
- GSC 请求成功：只报告“进入优先抓取队列”，不报告“已收录”；
- 连续三次出现同一阻塞：日报升级为醒目阻塞项，并请求用户处理必要登录或事实确认。

## 11. 验证闸门

站点变更提交前必须重新验证：

- 目标问题已被复现或有新鲜 GSC/生产证据；
- 变更行仅服务于当天目标；
- HTML、JSON-LD、sitemap XML 和 JavaScript 可解析；
- canonical、H1、可见 FAQ 与 schema 一致；
- 内部引用、图片和主要 CTA 无断链；
- Formspree endpoint 与回退邮箱一致；
- 桌面和 390px 手机视口无横向溢出，控制台无新增错误；
- Git diff 无无关格式化或用户改动；
- 生产正文、结构化数据和关键资源与本地变更一致。

## 13. 验收标准

设计实施完成需要同时满足：

- 当前任务中存在一个启用的每日 Heartbeat，按北京时间 07:30 运行；
- 没有重复的 MRT Buttons 增长自动任务；
- Heartbeat 提示词包含唯一正源、协作、登录、事实、提交和部署边界；
- 第一次运行能生成基线日报与无敏感信息的状态文件；
- 无变化时能安全 No-op；
- 模拟 P0、P1、P2 和登录失败时，决策与本设计一致；
- 用户能从每日输出看见目标、动作、证据、结果和下一步。

## 14. 依据

- 用户提供：《独立站建站后快速起流量实操手册》v1，2026-08-18；
- Google Search Central：生成式搜索优化仍建立在基础 SEO、可索引性和独有的 people-first 内容之上；
- Google Search Central：重复请求同一 URL 不会加快抓取，索引也不受保证；
- IndexNow：只为新增、更新、删除或迁移 URL 提交通知，HTTP 200 只表示接收；
- OpenAI：OAI-SearchBot 未被阻止是进入 ChatGPT Search 摘要与引用的基础条件之一。
